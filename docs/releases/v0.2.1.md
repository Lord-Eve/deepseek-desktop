清言工具调用兼容适配的本机试用版，保留原有 DeepSeek / 清言设置和模型名 `qingyan-default`。

升级前从托盘退出旧程序，解压完整新包并运行。同一 Windows 用户继续沿用保存的账号、端口和 API Key，无需重新获取清言 Token 或重配 Exa 凭据。

在原客户端为 `qingyan-default` 开启工具调用，并启用已经配置好的 Exa MCP。发送“请使用 Exa 搜索……，并根据搜索结果回答”，检查客户端是否展示真实的工具调用和搜索结果回传。测试的是外部 Exa 工具；模型仅声称自己进行了搜索不能视为通过。

- 支持 OpenAI `tools`、`tool_choice: auto/none/required`、指定 function 和 `parallel_tool_calls`。
- 返回 `tool_calls`、调用 ID、JSON 字符串参数；流式返回带 index 的工具事件及 `finish_reason: tool_calls`。
- 支持 `assistant.tool_calls` 历史、`role: tool` 结果和 `tool_call_id`，由客户端执行实际工具并将结果发送回来；桌面程序不执行 MCP 工具，也不读取 Exa 凭据。
- 基于提示词约定进行适配，不是清言原生 function calling。名称不匹配、参数缺失或类型错误、调用块损坏、上游未完成时会明确报错，不伪造工具执行成功。
- 带工具的请求使用网页通用模式，关闭内置搜索，先缓冲整条回复并校验再发送事件，因此初次输出比普通文本流式更晚。无工具请求保持逐段输出。
- 模型名仍为 `qingyan-default`，本次未扩展模型目录。不支持图片、音频、文件、Responses、Anthropic 路由或结构化输出约束。旧 `functions/function_call` 协议须改用 `tools/tool_choice`。

本次基础网关 29 项检查和新增工具适配 36 项检查已通过。新增检查包含非流式与流式“模型请求工具 → 测试客户端执行模拟 Exa → 按调用 ID 回传 → 生成最终回答”闭环，以及工具选择、参数校验、重复输出、截断和拒绝调用等边界。基础网关检查不访问真实上游，Exa 执行也为本地模拟。

用户已确认前版清言 API 可正常调用，并确认本版工具调用成功。模型对复杂工具 schema 的遵循程度、其他客户端兼容和跨时段稳定性仍需继续观察；本次用户验收不扩大为所有工具与所有场景均已通过。
