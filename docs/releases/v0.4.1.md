修复 Grok 测试消息的思考参数错误和不明确的错误提示。

## 本次修复

- 0.4.0 的测试按钮固定发送 `reasoning_effort=none`；grok-4.7 不支持关闭思考，可能因此返回上游 HTTP 400。本版改用 low，并添加真实测试请求生成逻辑的回归。
- grok-4.7 支持 low、medium、high、xhigh，grok-4.5 支持 low、medium、high。不支持的档位在本机明确报错；固定思考的 grok-4.20-0309-reasoning 移除可调档位字段。
- 上游 HTTP 400/422 参数错误保留原状态，日志和测试弹窗显示安全的错误代码、参数名；只展示白名单字段，不回显原始错误正文、对话或认证内容。不会因参数错误自动刷新登录或重放请求。
- 登录保存后选中已有账号，并明确说明可关闭浏览器页面；网页仍显示 code 不代表程序仍在等待输入。

官方思考档位参考：[xAI Reasoning 文档](https://docs.x.ai/developers/model-capabilities/text/reasoning)。本次已发现并修复确定的参数缺陷，但旧版丢弃了上游错误正文，不能排除另有拒绝原因。

## 更新与验证

0.4.0 用户可在“连接设置 → 数据与版本”检查更新，点击“下载并重启更新”。保留原账号、API Key、端口和连接设置。更新后选择已保存的 Grok 账号，启动服务，再发送测试消息；无需仅因这次参数错误反复登录。如果仍失败，请查看新的具体错误提示。

模拟检查覆盖非法/合法档位、固定思考模型、上游 400 分类、不重试及不泄露错误正文；WPF 检查覆盖实际桌面测试请求生成逻辑。未使用真实账号发送模型请求，不消耗额度，真实对话结果需更新后确认。发布由 GitHub CI 构建，不在用户的软件目录试装或下载发布包到本机。
