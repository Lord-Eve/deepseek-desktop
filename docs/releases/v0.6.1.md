修复 AstrBot 等客户端接入 CodeBuddy / WorkBuddy 时，两类正常请求被本地校验拒绝（400 `buddy_error`）的问题。

## 本次变更

- 无参数工具省略 `parameters`（或为 `null`）时，按空 object 处理后继续请求；显式给出但不是 object 的仍明确报错。AstrBot 对模型名含 gemini 的请求会省略这个字段。Chat Completions 和 Responses 都适用。
- Responses 历史中如果带有其他供应商（例如直连 Grok 时留下）的加密思考，不再导致整段对话一直报错。无法解密的密文被丢弃，可读摘要并入思考内容，没有摘要的项直接跳过。
- Responses 请求的 `include` 可以携带 `reasoning.encrypted_content`，本地接受但不会返回加密思考；其他 `include` 内容仍报错。

## 更新后使用

在“连接设置 → 数据与版本”点击“检查更新”，再点击“下载并重启更新”。账号授权、端口、API Key 和记住的服务状态保留。

## 验证边界

自动检查使用虚构凭据和模拟上游，未发送真实模型消息。AstrBot 实际请求 WorkBuddy gemini 模型、回放带 Grok 历史的会话，须更新后确认。发布包由 GitHub CI 执行完整发布检查并构建交付。
