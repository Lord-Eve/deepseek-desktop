新增软件内下载、替换并重启更新。

## 升级方式

0.3.x 及更早版本只会打开下载页，需要最后手动升级一次：退出旧程序，下载此版本完整 ZIP 并解压到常用软件目录，启动 0.4.0。同一 Windows 用户的账号、API Key、端口和其他设置继续沿用。

以后在“连接设置 → 数据与版本”发现新版本时，点击“下载并重启更新”即可。软件会下载、校验、退出替换并重启，原先运行的服务会恢复启动。下载期间可取消；“查看发布说明”保留为备用网页入口。

## 更新行为

- 私有仓库检查和下载沿用本机已登录 GitHub CLI 的权限，不需要粘贴 Token，也不读取或复制 GitHub 登录令牌。
- ZIP 与 SHA-256 一起下载，校验通过且版本匹配后才退出；检查包目录与文件路径，拒绝链接、越界、重复文件和不完整包。
- 独立更新组件等待原程序退出后替换文件，等待新程序完成初始化确认。替换或初始化失败时尝试恢复原文件；恢复也失败时保留备份并提示恢复位置。
- 账号、API Key 与连接设置保存在外部数据目录，不参与覆盖；软件目录内其他文件保留。软件目录必须可写，更新不自动提权，也不在 Git 工作区或目录链接中试装。
- 更新缓存位于数据目录的 `updates`；成功后清除下载、暂存和备份，正在运行的更新组件在下次正常启动时清除。失败备份保留，不自动删除。
- 替换阶段需要退出程序，本地 API 会短暂中断；尚未发送完的对话不会自动重放。Grok 的内存工具上下文会随服务重启清除，需要新建工具会话。

未下载真实发布包试装用户的软件目录；真实 GitHub 下载和完整已打包程序的升级由用户首次实际更新确认。发布由 GitHub CI 检查、构建和上传，不在用户本机 dist 准备更新包。
