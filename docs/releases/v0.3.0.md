## 使用方式

1. 退出旧程序，由你自行把完整新包解压到常用软件目录。不要同时运行旧版读取包含 Grok 平台的新设置；原有 Windows 用户数据目录、账号、API Key 和端口继续沿用。
2. 在“服务概览”选择“Grok OAuth（CLI 通道）”，进入“账号管理”，填写名称，点击“登录 / 重新登录 Grok”。
3. 在 xAI 官方浏览器页面确认授权，返回客户端。授权回调仅监听 `127.0.0.1:56121/callback`，最长等待 5 分钟，可取消；若其他程序正在登录 Grok，请先完成或取消它。
4. 启动服务后点击“发送测试消息”。启动只载入或刷新授权，不发送对话，也不读取账号额度。
5. 原客户端沿用本地地址与 Key，模型先使用 `grok-build`。确认普通回复后再开启已配置的 Exa MCP，验证工具调用、实际搜索结果回传和最终回答。

模型预设包括 `grok-build`、`grok-4.7`、`grok-4.5`、`grok-4.20-0309-reasoning` 和 `grok-composer-2.5-fast`。这只是参考目录，实际资格、可用模型及订阅额度取决于官方账号与服务器响应，不保证每个预设均可调用。

## 功能与边界

- 独立 OAuth 授权，不读取或复制 Cherry Studio / Grok CLI 的登录文件；无需粘贴 Token。仅可选读取 Grok CLI 的版本元数据作为客户端版本标记，不执行 CLI 或自动更新软件。
- 支持文本 Chat Completions 与 Responses，兼容原生函数工具声明、工具选择、流式工具事件和结果回传；MCP 仍由原客户端执行，不在本程序里重配 Exa 凭据。
- Grok 官方代理使用 Responses 协议。Chat Completions 工具会话需要保存上游加密思考与原始工具项，本程序仅在内存缓存：最多 128 项、总计 16 MB、有效期 30 分钟，绑定账号、模型和历史前缀。服务重启、过期或改写工具历史后，请新建会话。
- Responses 客户端直接处理原生事件及加密上下文，需发送完整历史；本适配强制 `store=false`，暂不接受 `previous_response_id`。Chat Completions 暂只支持文本，不保证图片/音频/文件转换。
- 首版每次启用一个 Grok 账号，同一时刻处理一个请求；最多等待 8 个请求，并沿用本机每小时上限。该上限不等同于官方额度。
- HTTP 401 仅在尚未接收事件流前刷新并重试一次；限流、服务异常、流式中断不自动重放。授权或订阅资格被拒绝后需停止并重新登录或选择可用模型。
- 使用自己的客户端标识，未冒充 Cherry Studio；参考其公开协议事实独立实现 C#。第三方适配不等于官方背书，真实服务是否接受本客户端仍需实测。
