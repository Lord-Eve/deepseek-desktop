修复 0.5.0 的 Buddy 客户端协议标识兼容问题，针对 WorkBuddy 国际版登录后获取模型目录或启动服务返回 `12403` 的反馈。

## 本次修复

- 将软件版本与上游产品协议版本分开。认证、模型目录和积分查询按国内／国际区域发送对应的兼容 UA；聊天按区域及模型族使用对应的产品归属和协议版本。
- 保持区域端点、账号凭据、本地 API 地址与 Key；软件版本通过独立字段标记，不再代替上游解析所需的产品版本。
- `12403` 明确提示客户端版本标识被拒绝、需要更新本程序，不再笼统显示账号或请求参数错误，也不回显上游原始正文。
- 继续采用原生 C# 接入，不需要安装或常驻官方 WorkBuddy／CodeBuddy 客户端、Harness 或 Node。

## 更新后使用

在“连接设置 → 数据与版本”点击“检查更新”，再点击“下载并重启更新”。更新保留已有账号授权、端口和 API Key。

更新后选择已保存的 WorkBuddy 国际版账号，先点击“获取账号模型列表”，成功后再启动服务并主动发送测试消息。无需仅因这次错误重新注册或安装官方客户端；若授权本身过期，再按程序提示重新登录。

## 验证边界

本地模拟检查覆盖两区认证、目录、余额和不同模型族聊天的实际请求构造，以及 HTTP 200／400 的 12403 提示和拒绝时不重放对话；没有读取真实账号凭据或发送真实模型消息。

匿名读取公开配置的两种 UA 均返回 HTTP 200 / code 0，因此匿名探针没有复现用户登录态下的拒绝，不能代替真实账号验证。用户账号的模型目录、真实对话和实际积分需更新后确认。发布包由 GitHub CI 执行完整发布检查并构建交付。
